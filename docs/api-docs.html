Dokumentasi Flowbeat API

Satu gerbang untuk data tanda vital dari tensimeter yang bentuk datanya berbeda beda. Data masuk apa adanya, lalu tersimpan dalam satu bentuk yang seragam, tersaring, dan tidak berganda.

Ikhtisar

Sistem terdiri atas dua layanan yang saling terpisah.

Omron (Bluetooth)→Bridge FastAPI→Klien penerus→Backend Laravel→MySQL
  • Bridge FastAPI membaca tensimeter lewat Bluetooth Low Energy dan mengembalikan JSON. Bridge tidak mengirim data ke backend.
  • Klien penerus, yaitu aplikasi mobile saat operasional, atau Postman dan k6 saat pengujian, memanggil bridge lalu meneruskan JSON-nya ke backend.
  • Backend Laravel mengenali perangkat dari mac_address, menyeragamkan data, menyaring data tidak masuk akal, mencegah duplikat, lalu menyimpan ke tabel patient_records.

Spesifikasi mesin tersedia di openapi.yaml, bisa diimpor ke Postman atau dibuka di Swagger Editor. Bridge juga menyediakan halaman uji otomatis di http://<ip-laptop>:8000/docs.

Autentikasi

Backend memakai Laravel Sanctum. Semua endpoint kecuali login wajib membawa tajuk berikut.

Authorization: Bearer 1|xxxxxxxxxxxxxxxxxxxx

Token dari login otomatis membawa dua kemampuan.

KemampuanDipakai oleh
ingest:writePOST /api/v1/ingest
monitoring:readGET /api/v1/monitoring/latest

Bridge FastAPI tidak memakai token, karena hanya berjalan di jaringan lokal laptop.

Bridge FastAPI

Semua endpoint bridge yang membaca perangkat memakai body yang sama, dan kelima atributnya wajib diisi.

sync_timebooleantrue untuk menyetel jam perangkat
pairingbooleantrue hanya saat pemasangan pertama, tidak membaca data

GET/api/v1/monitoring/latestmonitoring:read120 per menit

Data tanda vital terbaru untuk dasbor, lengkap dengan status klinis dari VitalSignClassifier.

{
  "status": "berhasil",
  "jumlah": 1,
  "data": [
    { "device_model": "HEM-7142T", "systolic": 120, "diastolic": 80, "pulse": 75,
      "measured_at": "2026-01-01 10:00:00", "quality_flag": "Verified", "status": "Waspada" }
  ]
}

Nilai status adalah Normal, Waspada, atau Tinggi. Status ini alat bantu pemantauan, bukan diagnosis.

Aturan kualitas

Dijalankan DataQualityService pada tiap catatan setelah diseragamkan. Satu catatan bisa melanggar lebih dari satu aturan.

Jam tensimeter yang belum disetel bisa diperbaiki dengan menyambungkannya sekali ke aplikasi Omron Connect di HP.

Pencegahan duplikat

Tiap catatan diberi sidik jari SHA-256 dari gabungan model perangkat, waktu pengukuran, sistolik, diastolik, dan denyut nadi. Sidik jari disimpan di kolom unik record_hash. Mengirim payload yang sama dua kali aman, pengiriman kedua hanya menaikkan duplikat.

Batas laju

Dihitung per token per menit. Ingest dibatasi 60 permintaan, pemantauan 120 permintaan. Permintaan berlebih dibalas 429 sampai menit berikutnya.

Saat uji beban dengan k6, naikkan sementara throttle:60,1 di routes/api.php, lalu kembalikan setelah selesai. Kalau tidak, hasil uji beban tercampur penolakan 429.

Menambah perangkat

  1. Buat kelas baru di app/Adapters/ yang mengimplementasikan VitalSignAdapter, dengan metode supports() untuk mengenali payload dan transform() untuk mengubahnya ke CanonicalVitalSign. Contoh paling sederhana ada di VendorBAdapter.php.
  2. Daftarkan kelas itu di AdapterRegistry.php.

Route, controller, aturan kualitas, dan skema basis data tidak perlu diubah. Untuk perangkat Omron seri lain, turunkan dari OmronBaseAdapter dan cukup isi macAddress() serta deviceModel().
